### Компиляция

```bash
npm run build
```

или

```bash
npx blueprint build
```

Эта команда соберёт все контракты из папки `contracts/` и сгенерирует TypeScript-обёртки в `wrappers/`.

---

### Как проверить, что компиляция прошла успешно?

1. **Отсутствие ошибок в терминале:** Если после выполнения `npm run build` в терминале нет ошибок (красного текста), компиляция прошла успешно.
2. **Проверка папки `wrappers/`:** После успешной компиляции в папке `wrappers/` должны появиться новые или обновлённые файлы с расширением `.ts` — это TypeScript-обёртки для ваших контрактов.
3. **Проверка папки `artifacts/`:** В некоторых конфигурациях Blueprint генерирует файлы артефактов (например, `.fif` или `.boc`) в папке `artifacts/`.

### Объяснение контракта `go_go_ton.fc`

Этот контракт — простейший пример смарт-контракта для TON, который демонстрирует два ключевых механизма:

- **Хранение данных в контракте** (состояние).
- **Обработка входящих сообщений** и **предоставление публичного метода для чтения данных**.

#### 1. Функция `recv_internal`

```func
() recv_internal(int my_balance, int msg_value, cell in_msg_full, slice in_msg_body) impure { ... }
```

- **Что делает:** Это основная функция, которая вызывается при получении контрактом внутреннего сообщения (например, транзакции).
- **Параметры:**
  - `my_balance` — текущий баланс контракта.
  - `msg_value` — количество TON, отправленных с сообщением.
  - `in_msg_full` — полное содержимое сообщения (включая заголовок и тело).
  - `in_msg_body` — тело сообщения (данные, которые отправитель хочет передать).
- **Логика:**
  - Извлекает адрес отправителя из сообщения (`sender_address`).
  - Сохраняет этот адрес в хранилище контракта (`set_data`).
- **Зачем:** Контракт запоминает, кто последний отправил ему сообщение.

#### 2. Функция `get_the_latest_sender`

```func
slice get_the_latest_sender() method_id() { ... }
```

- **Что делает:** Это публичный метод (геттер), который возвращает последний сохранённый адрес отправителя.
- **Как работает:**
  - Загружает данные из хранилища (`get_data`).
  - Извлекает и возвращает адрес (`load_msg_addr`).
- **Зачем:** Любой может запросить у контракта, кто последний отправил ему сообщение.

---

### Пример использования

1. Кто-то отправляет сообщение контракту → срабатывает `recv_internal`, контракт сохраняет адрес отправителя.
2. Другой пользователь вызывает `get_the_latest_sender` → контракт возвращает последний сохранённый адрес.

---

### Итог

- **Контракт** — это "коробка" с состоянием (данными) и логикой (функциями).
- **`recv_internal`** — обрабатывает входящие сообщения и обновляет состояние.
- **`get_the_latest_sender`** — позволяет читать состояние контракта.
